Task 1: Inspect a user-process page table
-----------------------------------------

A valid PTE with R, W, or X set is a leaf: it maps the virtual page to the
physical page frame encoded in the PTE. Adjacent virtual pages do not have to
map adjacent physical frames. A valid PTE with none of R, W, or X set is an
intermediate entry pointing to another page-table page. An all-zero PTE is
invalid and maps no page.

The permission letters mean read (R), write (W), execute (X), and user-mode
access (U). Thus an RXU entry such as permission value 0x5b is valid,
user-readable and executable, and not writable; it is typical for text. An
RWU entry is valid, user-readable and writable, but not executable; it is
typical for data, heap, and stack pages. An RW entry without U is
supervisor-only, as for the trapframe. An RX entry without U is
supervisor-only, as for the trampoline. In these example values, 0x5b also
has the accessed bit set, 0xc7 has accessed and dirty set, and 0x4b has
accessed set. These hardware status bits are included in the printed
permission value but are not R/W/X/U permissions.

The zero entry at virtual address 0xffffd000 in the supplied sample is
unmapped. In the completed lab, that slot is used by USYSCALL instead: it
contains the process ID and is readable by user mode but not writable.
The next high page is the supervisor-only read/write trapframe, and the final
page is the supervisor-only read/execute trampoline.

Task 2: Walk and print the page table
------------------------------------

vmprint starts at the level-2 root and recursively follows valid
non-leaf entries through levels 1 and 0. It prints a row for each valid
entry, including intermediate page-table pointers; indentation shows the
depth. The virtual address is formed from the indices visited along the
path. Each row prints the PTE, its extracted physical address, and any
R/W/X/U permission letters. Only leaf rows map actual memory pages; the
physical addresses on intermediate rows identify child page-table pages.

Task 3: Detect accessed pages
-----------------------------

pgaccess checks each requested user-page PTE for the hardware-maintained
accessed (A) bit and packs the results into a user buffer, with page zero
represented by the least-significant bit. It validates the page count,
address range, all requested mappings, and writable output buffer before
clearing any A bits. After collecting the mask, it clears the bits and
flushes the TLB so later accesses can be observed afresh. Invalid ranges,
unmapped pages, and invalid output buffers return an error.

Task 4: Speed up getpid
-----------------------

Each process owns a page containing its PID. The kernel maps it at USYSCALL
with read and user permissions, but without write permission, so ugetpid()
can read the value directly without entering the kernel. The page is
initialized during process allocation and released with the process. A
shared page could similarly speed up uptime() if the kernel published and
maintained a tick count there; that would require care to define consistent
reads while ticks are updated.

Task 5: Use kernel megapages
----------------------------

Kernel mappings use a level-1 leaf PTE whenever the virtual address, physical
address, and remaining mapping length allow an aligned 2 MiB page; other
portions remain mapped with 4 KiB pages. In the standard QEMU layout, the
64 MiB PLIC range uses 32 megapages. The aligned RAM range from 0x80200000
to PHYSTOP uses 63 more, for 95 megapage PTEs total. Each replaces 512
ordinary 4 KiB leaf PTEs and one bottom-level page-table page, saving 95
bottom-level page-table pages (380 KiB). vmprint identifies upper-level
leaf entries with a SUPERPAGE marker.
